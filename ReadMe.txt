# 🚀 Telegram-бот для IT-агентства / Веб-студии (Site IT)
> Data-Driven Lead Generation & Briefing Bot с интерактивной No-Code CMS прямо внутри Telegram.

Проект представляет собой асинхронный сервис на базе Python 3.11 + aiogram 3.13 + aiosqlite, автоматизирующий процесс первичной квалификации клиентов, сбора детального технического задания (брифа) по 28-страничному сценарию, предварительной оценки сметы и ведения воронки продаж.

## 🎯 Бизнес-задача и концепция

В традиционной модели веб-студии менеджеры по продажам тратят до 40–60 минут на первичный созвон с «холодным» клиентом, чтобы выяснить элементарные требования (тип сайта, интеграции, каталог, дизайн). При этом до 70% входящих лидов оказываются нецелевыми.

Данный бот решает эти боли:
* 100% первичного брифования: интерактивный опросник из 56 экранов проводит клиента по всем веткам (Новый сайт, Доработка, Продвижение, Портфолио).
* Соблюдение 152-ФЗ: экран политики конфиденциальности показывается клиенту строго один раз при первом входе и навсегда сохраняется в профиле.
* Повышение конверсии: благодаря встроенному калькулятору клиент сразу видит ориентировочную вилку цен и сроков, охотнее оставляя реальные контакты.
* Экономия для бизнеса: отказ от внешних конструкторов (Salebot, BotHelp) экономит студии от 25 000 до 40 000 руб./год (бот работает на собственном сервере за 99–500 руб./мес без ограничений по пользователям).

## 🏗 Архитектура системы (Data-Driven Engine)

Вместо жесткого хардкода 50+ обработчиков, проект построен на архитектуре интерпретатора графа экранов (State Machine Graph).

text
┌─────────────────────────┐         1 к M         ┌─────────────────────────┐
│       Таблица NODES     │ ────────────────────< │     Таблица BUTTONS     │
│ (ID, Текст, Тип экрана) │                       │ (ID, Текст, Действие)   │
└─────────────────────────┘                       └─────────────────────────┘
             │                                                 │
             │ привязка шага                                   │ - navigate (переход)
             ▼                                                 │ - toggle (чекбокс)
┌─────────────────────────┐                                    │ - url (ссылка)
│  Таблица USER_SESSIONS  │                                    │ - back (стек «Назад»)
│ (Стек истории + Ответы) │                                    │ - action (финализация)
└─────────────────────────┘
Основные компоненты:
nodes (Экраны): содержат тексты вопросов, тип поведения (regular, multiselect, input_text, input_file) и веса для расчета сметы.
buttons (Кнопки): хранят тип действия (navigate, url, toggle, back), целевой экран, веса (+₽ / +дней) и порядковый индекс (row_idx).
user_sessions (Сессии): хранят стек истории переходов в JSON для безошибочной работы кнопки «⬅️ Назад» и долгосрочные ответы клиента.
users (RBAC): база пользователей с матрицей из 5 гранулярных прав доступа для менеджеров.
leads (CRM): хранилище квалифицированных заявок с трехзначными кодами (#001, #002...).
📱 Клиентский функционал и воронка
Главное меню:
🆕 Заказать новый сайт (ветки: Товары, Услуги, Товары + Услуги, Свой вариант).
🆕 Доработать текущий сайт (CMS: WordPress, Tilda, 1C-Битрикс, OpenCart и др., список задач, доступы).
🆕 Продвижение сайта (Яндекс.Директ, SEO, Карты 2ГИС, Соцсети, геотаргетинг, цели).
🆕 Примеры наших работ (интерактивное портфолио по 7 нишам с кнопками-ссылками 🌐).
🆕 Связаться с нами (контакты студии, прямые ссылки).
Интеллектуальные чекбоксы (Мультивыбор):
Мгновенный отклик галочек [✅] / [⬜] без мерцания и перезагрузки сообщений.
Логика исключений: выбор пункта «Пока нет сайта» или «Не знаю» автоматически сбрасывает остальные чекбоксы.
Валидация выбора: клиент не может нажать «Готово», выбрав 0 пунктов (срабатывает нативный алерт).
Сохранение состояния: при переходе «Назад» и возврате все ранее выбранные галочки остаются на месте.
Безопасный ввод данных:
Валидация телефона (RegEx): проверка на корректность формата номера (минимум 10 цифр).
Валидация ссылок: отклонение бессмысленного текста, проверка наличия доменной зоны или Telegram-тега.
Прием файлов ТЗ: прием файлов любого формата без скачивания на диск сервера (хранение file_id).
Автосохранение профиля: имя и телефон запрашиваются 1 раз и подставляются автоматически в последующих заявках.
🛠 No-Code CMS: Полное руководство администратора
Управление ботом осуществляется через панель /admin прямо в Telegram без единой строчки кода.
1. Визуальный редактор экранов 
Под каждым экраном бота у администратора отображается служебная панель:
[✏️ Текст] — мгновенное изменение текста вопроса/сообщения (с защитой от сломанных HTML-тегов).
[➕ Кнопка] — пошаговый мастер добавления кнопок.
[⚙️ Кнопки] — управление составом и порядком кнопок на экране.
[👁 Вид клиента] — предпросмотр экрана глазами обычного пользователя (с кнопкой [🛠 Вернуться в редактор]).
[🗑 Удалить экран] — безопасное удаление кастомного экрана и всех ведущих на него связей (системные экраны защищены от удаления).
2. Конструктор новых экранов
При нажатии [➕ Кнопка] администратор может выбрать:
🆕 Создать НОВЫЙ экран под эту кнопку:
Вводит текст экрана (например: «Наши кейсы за 2026 год:»).
Выбирает тип: Обычный экран, Экран с галочками (мультивыбор) или Экран с вводом текста от клиента.
Для экранов ввода текста и чекбоксов выбирает, куда вести дальше (например, сразу к сбору контактов).
Результат: экран создается, на него автоматически вешается кнопка «⬅️ Назад», а ответы клиента с этого экрана автоматически дописываются в бриф заявки и в Excel!
➡️ Переход на существующий экран: выбор любого из 56 экранов по кнопке из списка.
🔗 Внешняя ссылка (URL): ввод ссылки на внешний сайт, канал или портфолио (с валидацией протокола).
3. Управление порядком кнопок (Сортировка)
В меню [⚙️ Кнопки] все кнопки экрана выводятся с номерами 1., 2., 3.:
Нажав на кнопку, можно переместить её кнопками [⬆️ Выше] / [⬇️ Ниже].
Либо нажать [🔢 Задать номер позиции] и отправить цифру (например, переместить 5-ю кнопку сразу на 2-е место).
4. Редактор сметы и сроков калькулятора
В /admin ➔ «🧮 Настройка сметы и сроков»:
Все платные опции сгруппированы по 5 понятным категориям (Магазин: 1С, Оплата, Функционал, Дизайн, Продвижение, Доработка).
Вместо безликих надписей отображаются понятные имена: 💳 Онлайн-оплата (+15 000 ₽, +3 дн.), 📊 Интеграция 1С (+30 000 ₽, +7 дн.).
Владелец кликает на пункт и отправляет новую стоимость и срок через пробел: 20000 4.
5. Управление персоналом и матрица прав (RBAC)
В /admin ➔ «👥 Персонал и роли»:
Добавление менеджера по @username или Telegram ID (человеку не обязательно запускать бота заранее — запись создастся в базе автоматически).
Готовые пресеты ролей в 1 клик:
👨‍💼 Менеджер продаж (CRM + Excel).
✍️ Контент-редактор (CMS + рассылки).
🧮 Сметчик-аналитик (Смета + Excel + аналитика).
👑 Управляющий (Полный доступ ко всему, кроме удаления владельца).
Индивидуальные тумблеры прав: [✅/⬜] Заявки, [✅/⬜] Excel, [✅/⬜] Смета, [✅/⬜] CMS, [✅/⬜] Рассылка.
6. Маршрутизация лидов и автопривязка группы
Привязка группы отдела продаж за 5 секунд: владелец добавляет бота в рабочий чат и пишет команду /set_leads_chat. Бот сам определяет chat_id и сохраняет в базу.
4 режима доставки лидов (в настройках агентства):
В группу + Владельцу в ЛС (максимальный контроль).
Только в группу отдела продаж.
Только Владельцу в ЛС.
Всем (в группу + всем менеджерам в ЛС).
7. Резервное копирование и сброс
[💾 Скачать бэкап (JSON)] — выгружает всю актуальную структуру экранов, кнопок и связей в один .json файл.
[📥 Восстановить из JSON] — администратор отправляет файл бэкапа документом, и бот мгновенно восстанавливает базу из файла.
[🔄 Сброс к заводским] — восстанавливает исходные 56 экранов из ТЗ. Заявки клиентов, база пользователей и настройки чатов при этом не затрагиваются.
🏆 Киллер-фичи проекта
Интеллектуальный экспресс-калькулятор сметы:
Суммирует базовые ставки и веса каждой выбранной клиентом галочки.
Формирует реалистичную вилку цен (140 000 – 180 000 ₽) и сроки (3–4 нед.), подогревая лид перед созвоном.
Интерактивная Mini-CRM в рабочем чате:
Карточка лида падает в группу с прямым тегом @username и ссылкой tg://user?id=....
Менеджеры меняют статус заявки прямо в Telegram кнопками: [🙋‍♂️ Взять в работу], [📞 Созвон], [🟢 Договор], [🔴 Отказ].
Двухстраничный аналитический Excel (.xlsx):
Лист 1: компактная CRM-сводка со статусами и цветовой подсветкой (без простыней текста).
Лист 2: построчная детализация всех ответов (реляционный вид EAV) для удобной фильтрации маркетологами.
Персональные системные команды (Telegram Scopes):
У обычных клиентов в меню Telegram отображаются только /start и /contacts.
Команда /admin видна в подсказках исключительно Владельцу и авторизованным менеджерам.

Настройка файла конфигурации .env
Создайте в корне файл .env по образцу:

BOT_TOKEN=
OWNER_ID=твой_цифровой_telegram_id
TIMEZONE=Europe/Moscow

Точка входа: main.py.

⚖️ Анализ: Сильные и слабые стороны реализации
💪 Сильные стороны (Архитектурные преимущества):
Data-Driven подход: разделение кода и данных. Весь диалог живет в БД, а код является масштабируемым интерпретатором.
Настоящий No-Code: добавление нового шага в бриф не требует вмешательства программиста — кастомные поля автоматически интегрируются в карточку лида и Excel.
Отказоустойчивость:
Защита от лимита callback_data (64 байта): используются компактные ID.
Защита от спама и двойных кликов: ThrottlingMiddleware (0.3 сек).
Защита от длинных сообщений: автообрезка текста при превышении 4000 символов в Telegram.
Защита от битого HTML: безопасный fallback-рендер без падения приложения.
Zero-Cost инфраструктура: сервер за 99 руб./мес заменяет громоздкие сервисы подписок.
⚠️ Слабые стороны текущего MVP:
SQLite под высокой конкурентной записью: SQLite использует блокировку на уровне файла. При 100+ одновременных кликах в секунду возможна задержка database is locked.
FSM MemoryStorage: сессии пользователей хранятся в оперативной памяти. При перезапуске сервера незавершенные промежуточные клики сбрасываются в исходную точку.
Long Polling вместо Webhook: для локального тестирования и дешевых VPS удобен Polling, но в Enterprise-решениях стандартом являются Webhooks.
Клиентский Drag-and-Drop: изменение порядка кнопок выполняется шагами или вводом индекса, так как нативный чат Telegram не поддерживает захват мышью.
🚀 Roadmap масштабирования в Enterprise-продукт
Для перевода решения в крупный коммерческий контур (от 100 000 пользователей):
Миграция БД на PostgreSQL (asyncpg + SQLAlchemy):
Разделение пула соединений, мгновенная обработка параллельных транзакций тысяч пользователей без блокировок.
Перенос состояний в Redis (RedisStorage):
Хранение FSM и кэша сессий в Redis — сохранение прогресса клиента при любых перезагрузках или обновлениях кода (Zero-Downtime deployment).
Telegram WebApp (Mini App) для конструктора:
Перенос No-Code конструктора из чата в визуальный WebApp с полноценным интерфейсом Drag-and-Drop (на базе Vue/React) прямо внутри Telegram.
Переход на Webhooks + Nginx:
Работа через реверс-прокси Nginx с SSL-сертификатом для мгновенного отклика без постоянных long-poll запросов.
Прямая интеграция с CRM (AmoCRM / Bitrix24):
Отправка сделок по REST API с созданием контакта, прикреплением файлов ТЗ и автоматическим назначением ответственного пайплайна.
Облачное S3-хранилище (Yandex Cloud / AWS S3):
Стриминг входящих файлов ТЗ напрямую в корпоративный S3-бакет с генерацией безопасных ссылок с ограниченным сроком действия.
